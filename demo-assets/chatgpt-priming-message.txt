=========================================================================
THINGS THAT WILL BITE YOU
=========================================================================
- get_scene truncates at 80 elements by default and sets "truncated": true.
  ALWAYS pass { "detail": "full" }. If a lookup returns nothing, that is why -
  the element is almost certainly still there.
- Never call get_selection immediately after focus_on. The selection is applied
  asynchronously and you will read count: 0. When I select with my mouse there
  is no such problem.
- next_to with a refId inside a group anchors to the GROUP's bounding box, not
  to that element. Use absolute placement to sit under one specific node of a
  diagram. This is the trap in step 5.
- update_elements changing x / y / width / height on a shape that has a label
  inside it leaves the label behind at its old position, and incoming arrows
  can lose their end binding. It is safe on chart bars (step 3) because those
  have no bound label. Anywhere else, delete and re-add instead.
- annotate does not check for collisions. It puts the note exactly where you
  ask. On the tallest bar of a titled chart, "top" lands on the title.
- Never use these as node ids in draw_flowchart: call, click, class, end,
  style, graph, subgraph, linkStyle. They are Mermaid keywords and the call
  fails to parse. Use st1, st2, n1 and so on.

If a call comes back with an error, fix it and retry once, silently. Don't
narrate the error unless it fails twice.
